# v0.9 音频修复与验收

## 本次确实修复的故障点

- 旧网页桥接只监听 touchend / click / keydown，未观察首次 pointerdown；AudioContext.resume() 的失败 Promise 被丢弃，拒绝后没有可见错误、明确状态或可靠重试路径
- 旧桥接强制 audioSession.type=playback，并循环播放隐藏的静音 HTML audio。新版本移除这条绕过系统静音行为的历史方案，遵守游戏保存的音乐/音效音量和设备静音策略
- 新桥接在实际玩家按下、释放或按键时恢复已有音频上下文；捕获拒绝和同步异常，挂起的恢复请求会释放重试状态，下一次真实操作可重试。准备中、被阻止和失败状态用小提示显示，提示不拦截操作
- 隐藏页面时暂停音频上下文，返回页面后等待下一次真实操作恢复；不制造、重复或吞掉玩家操作
- Web 音频改为 Godot Stream 混音，保留音乐低通总线。播放器的 Stream 枚举是 1，工程默认类型设置中的 Stream 枚举是 0，不可混用。原 WAV、播放器音量和总线滑块映射未改

Godot 官方说明 Web 默认 Sample 播放不支持 AudioEffects：[AudioServer](https://docs.godotengine.org/en/4.6/classes/class_audioserver.html)、[Web 导出音频说明](https://docs.godotengine.org/en/4.5/tutorials/export/exporting_for_web.html)。这解释了低通效果的后端差异，不能单独证明原项目完全无声

## v0.9 新增可选诊断

默认不显示诊断面板。在游戏网址末尾加 ?debug=audio，或游戏中按 F8 可打开/关闭；面板不拦截鼠标/触摸，F8 不取消或重放游戏输入

面板和 window.__pawAudioDebug() 显示 v0.9、实际保存的音效/音乐混音值、上下文状态/恢复次数，以及可观察时的 Worklet 模块请求 pending / fulfilled / rejected。快照中的 contextRunning 仅表示上下文运行，outputVerified 固定为 false，不假冒已听到声音

模块观察保持原始 addModule Promise、接收对象和参数。没有增加驱动回退、模块重试、替换音轨或增益变更。模块加载 fulfilled 也不能证明处理器节点已创建/连接、PCM 正在产生或设备可听

v0.8 的 Stream、启动顺序、手势恢复/重试、原始 WAV、增益和静音逻辑保持；Sfx 源文件校验与 v0.8 一致

## 启动时序

实际导出的 HTML 在引擎 index.js 前加载桥接；标准 Godot 页面自动调用 engine.startGame，音频上下文在 GodotAudio.init 初始化时创建，游戏菜单随后才可操作。没有新增“首次点击才异步启动引擎”的入口，因此没有照搬其他项目的暂停预热门

这是对导出脚本的静态时序检查，浏览器可能让上下文直接 running，也可能按自动播放规则保持 suspended。若玩家在加载阶段先点过，后创建的上下文仍明确等待下一次真实操作，不重放早先的操作

- 23 项实际 Godot 工程状态检查：50 个烘焙 WAV 预载、28 个音效播放器、三首音乐有效循环、Stream 类型、低通启用与复位、零音量静音、播放不重设静音、原始 UI 与音乐 dB、不重复改增益
- 28 项实际 Godot 加载导出 PCK 检查：以上状态及完整音频资源；生产包排除 autotest、烘焙工具及重复 HTML 文件
- Godot 4.6.3 官方无线程 Web 模板导出成功，导出 HTML 的注入内容与源文件及导出预设一致；工程未写入绝对模板路径

## 尚未通过真实设备验收

当前测试环境的本地网页浏览器入口被阻止，Chromium 本地连接权限也受限；实际提供的 Toy 页面可以检查外壳，但可用云浏览器因 WebGL2 不可用停在引擎播放前。没有继续尝试被阻止的资源路线或绕过限制。因此未取得实际浏览器 WebAssembly 播放、可听输出或 iPhone/Android 真机证据，不能把以上逻辑及资源检查称为“浏览器声音已听到”

原先用户遇到的整页无声，尚不能凭模拟与原生状态证据认定唯一根因。低端手机单线程 Stream 的延迟/杂音也需要真实设备检查

## 浏览器复测方法

1. 通过 HTTP(S) 打开 Web/index.html，全新加载后观察小提示，再做第一个正常菜单或游戏操作；原动作应照常执行，音频正常开启或明确显示重试
2. 使用 ?debug=audio 或 F8 查看 v0.9 诊断，也可在控制台执行 window.__pawAudioDebug()，检查 version、contextRunning、mix 与 contexts 的 state、attempts、successes、pending、error、worklet.modules。running 仅证明上下文运行，仍需实际检查设备输出
3. 若浏览器策略拒绝，下一次真实点击、触摸释放或按键应再次尝试；切后台应停止音频，返回后真实操作恢复
4. 分别设置音效和音乐为零并保存、重载，确认静音仍保留。设备静音不应被隐藏音轨绕过。再检查音乐/音效的非零音量与原有子弹时间低通效果
5. 手机分别检查首次触摸、移动+射击、前后台、系统静音及低端设备长时间播放，未完成这些检查前不标记真机通过
