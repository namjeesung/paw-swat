# 触屏操作参考：手机 / 平板上的移动、瞄准、射击

> 代码：`game/scripts/ui/touch_controls.gd`（触屏层）、`game/scripts/actors/player.gd`（`bot` 虚拟输入）、`game/scripts/world/game_camera.gd`（屏幕↔地面换算）、`game/scripts/autoload/game.gd`（震动、返回键、竖屏遮罩）。
> 数值都来自代码，改动时以代码为准。

---

## 1. 设计原则（从用户反馈里总结出来的）

| 反馈 | 真正的问题 | 原则 |
|---|---|---|
| 「WASD 移动时人物不转身」 | 没有鼠标时，朝向只跟着准星 | **没瞄准时朝向 = 移动方向**；在瞄准/射击时才朝向目标 |
| 「主要给手机和平板玩」 | 键鼠操作照搬不了 | 左手移动、右手开火，**开火键自带自动锁定**，单手就能打 |
| 「射击感觉非常奇怪、不听话」 | ① 目标在多个敌人间乱跳 ② 摇杆方向和画面方向对不上（45° 俯视透视压缩）③ 自动瞄准会打到人质 | **粘性锁定** + **等距视角方向修正** + **人质安全检测** |
| 「方向键和射击键不好使」（网页版） | 在 App 内置浏览器的小框里，按钮被缩得极小，还和系统手势抢触摸 | 按钮至少 44pt、远离屏幕边缘、在真正的 Safari 里玩（见第 7 节） |

调研参考：Archero（松手射击）、荒野乱斗 / Brawl Stars（拖动开火手动瞄准，点按自动瞄准）、使命召唤手游（瞄准辅助的吸附角度）、王者荣耀（点敌人头像切换目标）。

## 2. 屏幕分区

```
┌──────────────────────────────┬──────────────────────────────┐
│ 左上：狗牌血条 / 对讲 / 提示卡 │  点敌人 = 切换锁定（x > 40%） │
│                              │                     [暂停]   │
│   左半屏任意位置按下           │  右下（x > 50%, y > 30%）     │
│   = 浮动移动摇杆              │  = 开火区（按住 = 自动锁定连射）│
│   （出现在手指按下的位置）      │  [换弹] [冲撞] [翻滚] [上铐]  │
└──────────────────────────────┴──────────────────────────────┘
```

- **浮动摇杆**：手指按在哪里，摇杆中心就在哪里（`_move_origin = p`）。半径 `STICK_R = 120`，死区 `DEADZONE = 0.12`。手指拖出半径时**摇杆中心跟着手指走**（`_move_origin = _move_pos - v.normalized() * STICK_R`），不会出现「拖太远就失灵」。
- **开火区**：`_in_fire_zone(p)` = `p.x > 宽*0.5 and p.y > 高*0.3`。
- **圆形按钮的命中半径**（`RADII`）：翻滚 78、冲撞 78、换弹 62、上铐/破门 88、暂停 52（像素，1920×1080 画布坐标）。上铐/破门按钮可用时 `sin(t*8)` ±6% 呼吸缩放，吸引注意。
- **多指**：用 `event.index` 区分手指，`_move_idx`、`_fire_idx`、`_btn_idx[index]` 各管各的，移动 + 开火 + 点技能可以同时进行。
- **新手指接管**：左半屏任何新按下的手指都接管摇杆，右半屏（非按钮）的接管开火键。不要写成「`_move_idx == -1` 才接受新手指」——iOS 偶尔丢 `touchend`，那样摇杆会永久卡死。
- **按需出现的按钮**：【武器】（有神装时，`w-80, h-450`，半径 60，上方小圆点 = 拥有几把，圆心颜色 = 当前武器）、【手雷】（有手雷时，`w-760, h-230`，半径 62，右下角显示 ×n）、【上铐/破门/解救】（有互动目标时）。不出现时也不参与命中检测。
- **触摸调试**：网页地址加 `?debug=touch` 或命令行 `--touchdebug`，每根手指画圈标编号（青 = 摇杆，红 = 开火，黄 = 其他），屏幕上方列最近 8 条按下/抬起事件。

## 3. 开火与瞄准逻辑（`_feed()`）

触屏层不直接控制角色，而是每帧往 `player.bot` 这个**虚拟输入字典**里写值（键鼠、触屏、测试机器人共用这一套）：

```gdscript
b["move"] = mv                    # Vector2，长度 0~1
b["shoot"] = shoot                # 是否开火
b["aim_point"] = 世界坐标点        # 角色朝向 / 子弹方向
b["just_roll"] = true             # 一次性按键（just_*：roll / skill / reload / interact）
```

### 三种开火状态

| 状态 | 条件 | 瞄准方向 |
|---|---|---|
| **自动锁定连射**（默认） | 按住开火区，手指移动 < `MANUAL_DRAG = 42` 像素 | `_lock_dir()`：粘住当前目标 |
| **手动瞄准** | 按住后拖动超过 42 像素 | 拖动方向 → `screen_to_ground()` → `_soft_assist()` 7° 内轻吸附 |
| **松手射击**（暂停菜单里可切换） | 松开开火键时打一轮 | 有锁定打锁定，否则打拖动方向；一轮的时长：步枪 0.36s，激光 0.7s，加特林 0.5s，散弹/火箭 0.05s（单发） |

### 粘性锁定（解决「目标乱跳」）

```gdscript
func _lock_dir() -> Vector3:
	if lock == null or not _can_hit(lock):   # 只有原目标失效才换
		var nl := _pick_target()
		if nl:
			lock = nl
	...
```

- 锁定距离 `LOCK_RANGE = 13.5` 米，超出 +2 米才丢失锁定（有回差，防止边界抖动）。
- **挑目标打分**：`score = 距离 × (1 + 0.35 × (1 − 面前程度))`，优先打面前的，避免突然转身打背后。
- `_can_hit`：要有清晰射线（`level.clear_shot`，墙和高掩体会挡）**并且**人质安全。
- 点一下敌人（右半屏、非开火区、`_enemy_at(p)` 命中）= 手动切换锁定，震动 15ms + 提示音。
- 正在锁定的敌人脚下画**红色方框**（`_reticle`），候选目标画弱一些的框。每 0.15 秒重新算一次候选（`_cand` 节流）。

### 等距视角的方向修正（解决「方向对不上」）

相机俯仰 −45°，地面在屏幕上被压扁了 sin(45°) ≈ 0.707 倍。直接把摇杆的 (x, y) 当成地面方向，斜着推的时候就会偏。修正：

```gdscript
func screen_to_ground(v: Vector2) -> Vector3:
	var s := sin(deg_to_rad(-PITCH))
	var w := ground_right() * v.x - ground_forward() * (v.y / s)
	return w.normalized() * minf(v.length(), 1.0)
```

移动摇杆和手动瞄准都走这个函数，所以「手指往哪推，角色就往屏幕上的哪个方向走」。

### 人质安全检测（解决「自动瞄准打到人质」）

```gdscript
# 射线 玩家→目标 延长到目标后方 8 米（打偏的子弹会继续飞）
var over := 1.0 + 8.0 / maxf(ab.length(), 0.5)
var t := clampf(ap.dot(ab) / ab.length_squared(), 0.0, over)
var ok := (ap - ab * t).length() > 1.0 and 人质到目标距离 > 1.4
```

不安全的目标不会被自动锁定，第一次出现时提示「人质在旁边 —— 拖动开火键手动瞄准！」。神装武器的子弹带 `safe` 标记，不伤人质。

### 其他手感细节

- 触屏时步枪散布更小（手指瞄不准，补偿一点）。
- 锁定目标时子弹有轻微追踪（`lock_target` 传给 `Player`）。
- 受击后 0.4 秒无敌，防止被围时瞬间蒸发；被打时**不顿帧**（只有打中敌人才顿）。
- 冲撞冷却中再按会弹「冷却中 x 秒」小提示，而不是没反应。

## 4. 反馈：震动、声音、视觉

| 动作 | 震动 | 其他 |
|---|---|---|
| 按下任何圆形按钮 | 12ms | 按钮闪白（`_flash[b] = 1`，每秒衰减 4） |
| 按下开火区 | 8ms | — |
| 点敌人切换锁定 | 15ms | `telegraph` 音效，音高 ×1.6 |
| 玩家受伤 | 40ms | 镜头震 0.4、屏幕边缘红 |

`Game.vibrate(ms)` 只在触屏模式、设置里打开震动、且平台是安卓或安卓浏览器时生效（iOS 网页不支持震动 API）。

## 5. 触屏布局（`Hud._touch_layout`）

- 原则：**底部两个角留给拇指，信息全部挪到顶部**。
- 狗牌血条缩到 0.8 倍放左上；对讲在它下面（y=176）；**新手提示卡再往下（y=332），连杀计数在提示卡下面**。屏幕中间不放任何常驻 UI。
- 右上：计时器、案件名 + 难度标签（避开暂停按钮）、暂停按钮。
- 键鼠专用的弹药面板、技能栏、准星、按键提示全部隐藏，改由触屏按钮自己画（按钮里显示弹药数和冷却扇形）。

## 6. 平台细节

- **触屏检测**（`Game.touch`）：`mobile`、`web_android`、`web_ios` 特性，或网页上 `DisplayServer.is_touchscreen_available()`，或命令行 `--touch`（电脑上预览手机布局）。
- **横屏**：`project.godot` 里 `handheld/orientation = 4`（传感器横屏）。网页不能锁方向，所以竖屏时盖一层「请把手机横过来」遮罩并自动暂停。
- **安卓返回键**：`quit_on_go_back = false`，返回键 = 打开暂停菜单；切到后台（`FOCUS_OUT` / `PAUSED`）自动暂停。
- **网页虚拟键盘**：`html/experimental_virtual_keyboard = true`，起昵称、输恢复码时能弹出系统键盘。

## 7. 网页版在 iPhone 上（v0.6 的经验）

### 7.1 iOS 网页的限制

| 现象 | 原因 | 对策 |
|---|---|---|
| 没有声音 | ① 侧边**静音开关**会让 Web Audio 完全静音 ② iOS 只在 `touchend` / `click` 里允许恢复 AudioContext | `head_include` 里：包装 `AudioContext` 构造函数以便拿到实例；设置 `navigator.audioSession.type = "playback"`；循环播放一段 0.2 秒的静音 `<audio>`（把音频会话切到「播放」类，不受静音开关影响）；在 `touchend`/`click`/`keydown` 里 `resume()`（监听器用 passive） |
| 双指缩放、长按弹菜单、页面回弹 | Safari 默认手势 | canvas 上 `touch-action:none`，body 上 `-webkit-touch-callout:none; user-select:none; overscroll-behavior:none`，`gesturestart` 调 `preventDefault()`。**不要**在 document 上拦截 `touchmove` / `dblclick`：v0.6 这样做之后 iOS 上摇杆失灵 |
| 不能自动全屏 | **iPhone 的 Safari 不支持元素全屏 API**（只有视频能全屏；iPad 可以） | ① 让玩家「分享 → 添加到主屏幕」（PWA：Godot 导出选项 `progressive_web_app/enabled`，display = fullscreen，横屏）；② 横屏后在 Safari 地址栏菜单里「隐藏工具栏」；③ 做原生 iOS 版 |
| 按钮极小、手势冲突 | 在 B 站 App 等内置浏览器里，游戏被嵌在一个又小又扁的框里（实测约 1118×255，宽高比 4:1），左边缘滑动会被当成「返回」 | 用 Safari 打开；按钮按物理尺寸设下限（苹果建议 ≥ 44pt）；摇杆区避开屏幕边缘 |

代码在 `game/web/head_include.html`（同一段内容写在 `export_presets.cfg` 的 `html/head_include` 里，导出时注入网页 `<head>`）。调试时在浏览器控制台运行 `__pawAudioDebug()`，会列出所有 AudioContext 的状态。

### 7.2 嵌在第三方平台（如 bilibili TOY）里时

- 外层页面（标题栏、白边、框的尺寸和比例）由平台控制，游戏代码改不了；要查平台文档里有没有「横屏 / 全屏 / 自定义尺寸」配置。
- 游戏要能适应**极端宽高比**：`canvas_items + expand` 会按较短边缩放，框越扁 UI 越小。对策：触屏模式下按真实像素高度给按钮设下限，或宽高比超过某个值时两侧留黑边。
- 在电脑上用 Chromium 模拟触屏只能验证「没有报错、布局正确」，**手感、声音、系统手势必须在真机上测**。

## 8. 测试触屏（不需要真机的部分）

`--autotest --touch --touchtest`：机器人往视口里注入 `InputEventScreenTouch / ScreenDrag`，依次验证：摇杆能走、开火区能锁定连射、拖动能手动瞄准、点敌人能切换、各按钮能触发，最后打印 `[touch] RESULT PASS`。

坑：注入的坐标要先乘视口的最终变换，并且窗口要和目标设备同比例：

```gdscript
var screen_pos := get_viewport().get_final_transform() * canvas_pos
```

建议同时跑两个分辨率：手机 `--resolution 2400x1080`、平板 `--resolution 2048x1536`。
