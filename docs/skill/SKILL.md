## 核心理念（先读这一段）

1. **先设计，后编码。** 第一份交付物是剧本 + 设计稿（世界观、角色、关卡流程、配色、界面隐喻、手感清单），用户确认后才写代码。设计稿就是之后每一轮的验收标准。
2. **一切用代码生成。** 角色、场景、图标、UI、音效、音乐全部由代码搭出来：没有美术素材也能做出完整、统一的画面，改起来也快。之后可以逐个替换成正式资源。
3. **手感是第一优先级。** 用户能看到、能摸到的东西都要有反馈：没有任何数字、面板、按钮是「啪」一下瞬间出现的。
4. **面向手机设计操作。** 键鼠只是附带；触屏要单手能打（自动锁定），也要能精确操作（拖动手动瞄准）。
5. **所有数值都集中管理。** 用命名常量和集中的数值表（配色 `Pal`、武器 `Weapons.DATA`、难度 `Game.DIFFS`），调参不用到处找代码。
6. **机器人真的在玩游戏。** 每一轮修改都让测试机器人从菜单打到结算，拿截图和卡顿数据说话，然后才打包交付。
7. **每次反馈先拆成具体问题。** 例如「射击不听话」拆成「目标乱跳 / 方向对不上 / 误伤人质」三条，每条对应一个方案，交付时逐条说明。

## 工作流程

### 第 0 步：剧本与设计稿（不写代码）

产出一份 `docs/SCRIPT.md`，至少包含：

- **一句话卖点** + 题材 + 视角（例：2.5D 45° 俯视、猫狗特警打匪徒）。
- **角色表**：主角（能力、口头禅）、敌人种类（各自的行为和「可读性」提示，例如浣熊开枪前亮红色激光）、平民/人质。
- **关卡流程**：分阶段写清楚目标（进店 → 清场 → 破门 → 救人质 → 高潮 → 结算）。
- **核心机制**：射击、翻滚、技能、非致命制服（击倒后上铐）、掩体、完美换弹等。
- **美术方向**：卡通渲染 + 描边，统一调色板（写出 hex），角色由简单几何体拼成。
- **界面隐喻**：每个界面对应一个现实物件（主菜单 = 警局软木任务板，简报 = 局长的投影仪，暂停 = 对讲机，结算 = 报纸头版 + 评级印章，转场 = 警戒线胶带）。
- **手感清单**：顿帧、震屏、子弹时间、弹壳、跳字、连杀……

先给用户看，按反馈改，再进入开发。

### 第 1 步：工程骨架

- Godot 4.x，渲染器用默认设置即可：安卓走 Mobile 渲染器，网页导出自动用 Compatibility（WebGL2）。画面只用卡通材质 + 少量灯光 + 雾，三种渲染器下观感一致；截图测试用 `--rendering-driver opengl3`。
- 画布 1920×1080，`stretch/mode = canvas_items`，`aspect = expand`；手机横屏 `handheld/orientation = 4`。
- 主场景只放一个 `main.gd`，**所有界面由代码搭建**。
- 自动加载（autoload）：
  - `Game`：界面切换 + 转场、时间控制（顿帧/子弹时间）、设置、本局统计、难度表、输入映射。
  - `Sfx`：音效和音乐。
  - `Online`：排行榜（身份、本机记录、云端请求）。
- 目录：`core/`（配色、样式、卡通材质、建模、特效）、`actors/`（玩家、敌人、子弹）、`world/`（关卡、地图搭建、相机）、`ui/`（各界面和 HUD）、`test/`（测试机器人）、`tools/`（离线工具）。

### 第 2 步：程序化美术

- **卡通材质 + 描边**：主材质 `StandardMaterial3D`（`DIFFUSE_TOON` + `SPECULAR_TOON` + 一点边缘光 rim 0.3；预先打开黑色自发光，受击闪白时只改自发光颜色），`next_pass` 挂一个描边材质（`cull_front` + 顶点沿法线外扩 `grow`）。描边颜色按阵营区分：我方暖棕、敌方深紫、平民青色。
- **角色 = 几何体拼装**（`CharModel`）：`pose`（整体，用于倒地、翻滚）→ `body`（身体，用于走路上下颠、挤压拉伸）→ `head`、`gun`、两只脚。眼睛用黑球 + 白色高光小球。不同角色只是换颜色、耳朵、尾巴、帽子。
- **场景** 用盒子拼：地板格子、货架（上面放彩色小方块当商品）、收银台、纸箱、警车、路灯、路障。碰撞层分清楚：墙、高掩体、低掩体（低掩体近距离可以越过去射击）。
- **世界里的 UI** 用 `Label3D`（倒计时、「可上铐 12s」、对话气泡）。

### 第 3 步：相机与操作

- **正交相机**：偏航 45°、俯仰 −45°，`size ≈ 15.5`；跟随玩家时往瞄准方向偏一点，平滑跟随用 `lerp(a, b, 1 - exp(-k·dt))`。
- **屏幕方向 ↔ 地面方向** 要修正透视压缩（除以 sin 45°），否则斜着推摇杆会走歪。
- **虚拟输入层**：角色只读 `player.bot` 字典（`move / shoot / aim_point / just_roll …`），键鼠、触屏、测试机器人都往这个字典里写值。这一层是后面触屏和自动测试几乎零成本接入的关键。
- **朝向规则**：没在瞄准时朝移动方向转身；瞄准/射击时朝目标。
- 触屏方案（浮动摇杆、按住开火自动锁定、拖动手动瞄准、点敌人切换、松手射击模式、人质安全检测）→ `references/mobile-controls.md`。

### 第 4 步：战斗与打击感

最低配置，缺一不可：

- **命中**：敌人闪白 + 挤压、跳伤害数字、火花、命中音；最后一击加顿帧（约 0.05~0.07 秒）+ 震屏。
- **顿帧有上限和冷却**（最长 60ms，间隔至少 350ms），否则连发武器会让游戏「粘住」。
- **开枪**：枪口火光（可带一盏短暂的点光源）、弹壳抛出（数量上限 36）、后坐力让枪身后缩、镜头微震。
- **翻滚有无敌帧**，躲过子弹时跳「闪避!」；受击后 0.4 秒无敌。
- **敌人开枪前有预警**（红色激光 0.5 秒），给玩家反应空间。
- **非致命制服**：击倒 → 头上转星星 + 倒计时 → 走过去上铐（永久制服，加分）→ 倒计时结束会醒来。
- **完美换弹**：换弹进度条上有黄色区域，按中瞬间装满 + 火力强化，按早卡壳。
- **破门**：撞门瞬间进入子弹时间（世界 0.25 倍速，玩家相对更快）。
- 详细数值和缓动 → `references/juice-and-animation.md`。

### 第 5 步：UI 系统

- 选一个**设计隐喻**贯穿全部界面（这里是「贴纸 / 警局档案」）：粗描边、圆角、轻微旋转、阴影偏移、贴纸按钮按下会「压扁」。
- 三种字体分工：标题（站酷快乐体）、正文（思源黑体，按用到的字做子集）、数字（Bungee）。全部是 OFL 开源字体。
- 所有颜色来自调色板常量；UI 组件封装成可复用的类（贴纸按钮、狗牌血条、罐头弹药、对讲机对话框、目标药丸、提示卡）。
- **HUD 分两套布局**：桌面版信息分散在四角；触屏版把底部两个角留给拇指，信息全部放到顶部，屏幕中间不放常驻 UI。
- 详细规范 → `references/ui-design.md`。

### 第 6 步：音效与音乐

- 全部用代码合成（正弦/方波/三角/锯齿 + 噪声 + 包络 + 频率滑动），音乐用简单的鼓 + 贝斯 + 和弦循环。
- **运行时合成会卡顿**：做一个离线工具把所有声音烘焙成 WAV，游戏里只预载 WAV。
- 暂停时给音乐总线加低通（「闷」掉），恢复时撤掉。
- 配方和混音音量 → `references/audio.md`。

### 第 7 步：关卡流程与目标引导

- 用 `phase` 变量推进阶段，每个阶段更新顶部「目标」药丸（如「清除店内匪徒 3/8」）。
- **目标要一眼看懂**：地上的橙色箭头一路指向目标、关键时刻镜头飞过去给人质/新目标一个特写再飞回来、局长对讲提示下一步。
- 导航网格在关卡开始时烘焙一次（门建好之前，门洞是通的），之后不要在运行时重新烘焙。
- 掉落物和动态生成的东西用 `safe_drop_point`：不穿墙、离墙至少 1.1 米、只吸附到附近的导航点。

### 第 8 步：高潮段落

普通关卡之后要有一个「爽」的收尾：

- 前面战斗中掉落**神装武器**（群攻：散弹、贯穿激光、火箭、加特林），伏笔。捡到的神装进**武器库**，可随时切换（Tab / 触屏武器键），同种叠加弹药，打空才消失——不要「捡一把顶掉一把」。
- **范围道具**（罐头手雷）：落点先出红色范围圈，引信越闪越快再爆炸；第一次击倒必掉（教学），之后按几率掉。
- 救下的人质**不要留在战场里**：自己沿导航跑到警车、上车、警车鸣笛开走，玩家心里「这件事完成了」，后面专心打。
- 高潮：**可爱款僵尸鼠潮**，坚守 60 秒，中途出 Boss（数量随难度 1 / 1 / 2 / 3，多只时单只血量适当降低）。
- 拿到神器时插一段 **30 FPS 像素风变身动画**（SubViewport 320×180 + 最近邻放大 + 每 1/30 秒才推进一帧），然后满屏大字「FIRE!」+ 喊叫音效。
- 结尾空投轰炸 + 白闪 + 慢动作 → 结算报纸。

### 第 9 步：新手提示

- 每种机制**第一次出现时**弹一张提示卡（图标 + 标题 + 一两句说明），几秒后自动收起；暂停菜单里能随时翻看全部说明。
- 卡片放在屏幕**左侧**（对讲下面），**不要挡住屏幕中间**。
- 正文里的关键字用 `{关键字}` 标记，渲染成红色加粗。
- 触屏和键鼠两套措辞（「点【上铐】」vs「按 E」）。
- 坑：淡入和淡出不能同时进行（否则卡片永远不消失）；排队太久的提示要丢掉，等那个机制下次出现再弹。

### 第 10 步：难度

- 所有难度参数放一张表（`Game.DIFFS`），代码里只通过 `Game.dv("key")` 读取。
- 档位之间**差距要大到一上手就能感觉到**：同时改玩家血量、敌人血量、**敌人数量**（追加站位）、敌人节奏（预警时长、攻击冷却、连发数）、僵尸上限、Boss 数量、人质容错次数。
- 难度选择放在出发前的简报页，选中有反馈（最高难度按钮持续抖动、闪红、警报音），并记住上次的选择。
- 每个难度单独排行。

### 第 11 步：排行榜与防作弊

- 身份：**游客 ID + 昵称 + 恢复码**（换设备用恢复码找回），服务器只存恢复码的哈希。
- 防作弊（Cloudflare Worker + D1）：每局开始领一次性令牌（服务器记录开局时间、绑定难度）→ 提交时校验：用时不能短于服务器实际经过的时间、不能低于关卡物理下限、必须真的完成关卡、令牌只能用一次、限制开局频率。
- 没部署服务器时只记本机成绩，界面照常工作。

### 第 12 步：性能

- 写一个卡顿记录器（帧时间 > 50ms 记一次，带上当前步骤名），先测量再优化。
- 常见元凶：运行时合成音频、着色器首次编译（加载时预热）、每帧新建材质（缓存）、无上限的粒子/弹壳、运行时重新烘焙导航、顿帧叠加。

### 第 13 步：测试与验收

- 测试机器人：完整流程、无敌模式、指定难度、直接跳高潮、触屏注入、排行榜提交、截图。
- 每一轮必须：① 机器人通关 ② 看截图（布局、遮挡、文字溢出）③ 看卡顿统计 ④ 网页版在浏览器里无报错。
- 能自动化检查的 BUG 就写成检查：比如提示卡挂超过 15 秒打印 `STUCK`，掉落物打印修正前后的位置。
- 详细命令 → `references/pipeline-and-testing.md`。

### 第 14 步：导出与交付

- 安卓：只打 arm64（体积减半），用 debug keystore 签名；每次发版递增 `version/code`。
- 网页：无线程模板（iPhone Safari 和各种内置浏览器都能跑），`head_include` 注入 iOS 音频解锁和防缩放。
- 交付三件套：APK、网页 zip、源码 zip（工程 + 服务器 + 文档），每个包附 `说明.txt`，单个文件 < 30MB。

### 第 15 步：处理用户反馈

1. 复述反馈，拆成可验证的具体问题（必要时先调研同类游戏怎么做，给出方案，等用户同意再改）。
2. 用户说「先不改代码」时，只做分析和方案。
3. 改完用机器人复现「修之前坏 / 修之后好」，截图对比。
4. 交付时逐条说明改了什么、测了什么、**哪些没法在这里测**（例如 iPhone 真机上的手感和声音）。

## 检查清单

**每个新机制**
- [ ] 有输入反馈（音效 + 视觉 + 触屏震动）
- [ ] 有新手提示卡（触屏 / 键鼠两套措辞，关键字标红）
- [ ] 触屏上能操作（按钮够大、不挡视线、不和其他手势冲突）
- [ ] 测试机器人会用它（或者至少不会被它卡住）
- [ ] 参数是命名常量，受难度表影响的走 `Game.dv()`

**每次交付前**
- [ ] 机器人通关（普通难度不开无敌；高难度至少无敌模式能走完）
- [ ] 截图检查过桌面和手机两种布局
- [ ] 卡顿统计没有变差
- [ ] 网页版浏览器里无报错
- [ ] 版本号递增，临时改动已还原，代码已推送
- [ ] APK / 网页 zip / 源码 zip 都 < 30MB，附说明

**手机网页（iPhone）**
- [ ] 网页外壳**不要**在 document 上拦截 touchmove / dblclick（v0.6 因此摇杆失灵）
- [ ] 触屏层「新手指接管」摇杆和开火键（iOS 会丢 touchend）
- [ ] 有触摸调试叠层（`?debug=touch`），真机问题让用户录屏
- [ ] 静音开关打开时也有声音（`audioSession = playback` + 静音 `<audio>`）
- [ ] 双指缩放、双击放大、长按菜单、页面回弹都被禁止
- [ ] 竖屏有「请横过来」遮罩并自动暂停
- [ ] 知道 iPhone 网页不能自动全屏：引导「添加到主屏幕」或在 Safari 里隐藏工具栏
- [ ] 嵌在第三方平台的小框里时，按钮仍然够大
