## 阶段 1：先写剧本和设计稿，不写代码（`docs/SCRIPT.md`）

### 用户需求
> 做一个 2.5D、45° 俯视的第三人称射击游戏，猫狗特警打匪徒，要有**设计感、操作手感、UI 交互**。

### 决定：第一份交付物是设计文档
需求里三个关键词都是「感觉」类的，直接写代码很容易做成「能玩但没味道」。所以先交一份可评审的设计稿，把「感觉」翻译成可执行的清单：

| 章节 | 作用 |
|---|---|
| 一句话卖点「毛茸茸的手感，硬核的破门」 | 所有取舍的锚点：可爱外表 + 有分量的操作 |
| 世界观 / 角色表 / 敌人表 | 给美术和关卡提供素材：柴犬豆包（主角）、浣熊打手、老鼠小毛贼、仓鼠人质小米、局长老灰 |
| 5 章剧情 + 序章教学关 | 确定 MVP 范围 = 序章「午夜便利店」 |
| 核心玩法 + 关键系统 | 掩体自动蹲、破门子弹时间、非致命上铐、完美换弹、S/A/B/C 评级 |
| **手感清单**（第六节） | hit-stop 30~60ms、白闪、击退、跳字、枪口火光、弹壳、后坐镜头、前瞻镜头、翻滚残影、动态准星、受击方向指示、低血红边 + 心跳 |
| **界面设计**（第七节） | 「警局档案 × 潮玩」：主菜单 = 软木任务板，简报 = 局长投影，HUD = 狗牌血条 + 罐头弹药，暂停 = 对讲机，结算 = 报纸头版 + 评级印章，转场 = 警戒线胶带 |
| 配色表 | 藏青 `#1B2A4A` / 警示橙 `#FF7A1A` / 奶油白 `#FFF4E0` / 匪帮紫 `#6B3FA0` / 警报红 `#E63946` |
| 美术方向 | 低多边形 + 正交 45° + 卡通着色 + 描边；**我方暖色描边、敌方紫色描边** |
| 待确认问题 | 游戏名、基调、反派动机、**平台优先级**、第一版范围 |

> 经验：设计稿最后的「待确认问题」非常重要。「平台优先级」这个问题后来决定了整个项目的走向（用户回答：手机/平板为主）。

## 阶段 2：技术选型 + 程序化骨架（v0.1，`e95f510`）

### 为什么选 Godot 4.5
- 免费、单文件可执行、headless 模式能跑完整游戏（自动测试的前提）、能导出安卓和网页。
- GDScript 写 UI 和工具都快；正交相机、Toon 漫反射、`next_pass` 描边都是内置能力。

### 为什么「一切都用代码生成」
- 没有美术资源，也不想用来路不明的素材；代码生成的东西风格天然统一。
- 每个模块都能被测试机器人构造出来；改配色 / 尺寸只改常量。
- 场景树只有入口：`main.tscn` → `main.gd` → `Game.boot(self)`，之后 `Game._show()` 按名字 `new()` 出 `MainMenu / Briefing / Level / Results / LeaderboardScreen`。

### 骨架

| 层 | 文件 | 职责 |
|---|---|---|
| 自动加载 | `autoload/sfx.gd` | 音效/音乐（28 个 `AudioStreamPlayer` 轮询池 + 音乐播放器 + 总线） |
| | `autoload/game.gd` | 界面切换 + 警戒线转场、时间控制（顿帧/子弹时间）、震屏、设置存档、本局统计、难度表、输入映射（代码里 `InputMap.add_action`） |
| | `autoload/online.gd` | 排行榜（v0.4 加入） |
| 核心工厂 | `core/pal.gd` `style.gd` | 配色常量 / 字体 + StyleBox + Label 工厂 |
| | `core/toon.gd` | 卡通材质 + 描边 + 发光材质（带缓存） |
| | `core/models.gd` `char_model.gd` | 几何体缓存 + 各角色建模 + 程序化动画 |
| | `core/fx.gd` | 特效工厂（全部自管理生命周期） |
| 角色 | `actors/*.gd` | `Actor` 基类（血量/朝向/击退/圆形投影）→ Player / Enemy / Zombie / Hostage；`Bullet` |
| 世界 | `world/*.gd` | `Level` 流程、`MapBuilder` 搭场景、`GameCamera`、`Door`、`GroundGuide`、`Pickup` |
| UI | `ui/*.gd` | 每个界面一个类，HUD 小部件全部 `_draw()` 自绘 |

### 关键实现

**卡通描边（inverted hull）**：`Toon.mat()` 给每个材质挂一个 `next_pass`：不受光、`CULL_FRONT`、`grow = true`、`grow_amount = 0.022`（角色用 0.024）。描边颜色按阵营区分：我方 `OUTLINE_HERO #4A2208`、敌方 `OUTLINE_ENEMY #2E1450`、人质 `OUTLINE_CIVIL #0F4F49`、道具 `OUTLINE_PROP #1A2033`。材质预先 `emission_enabled = true, emission = BLACK`，受击闪白时只改 emission 颜色，不换材质（不触发着色器重编译）。

```gdscript
static func outline_mat(color: Color, width: float) -> StandardMaterial3D:
	var o := StandardMaterial3D.new()
	o.shading_mode = BaseMaterial3D.SHADING_MODE_UNSHADED
	o.cull_mode = BaseMaterial3D.CULL_FRONT
	o.grow = true
	o.grow_amount = width
	o.albedo_color = color
	return o
```

**角色 = 基础几何体拼装**：`CharModel` 层级是 `CharModel(朝向) → pose(倒地/翻滚) → body(上半身摇摆) / feet`，头、枪、尾巴、手铐是 body 下的子节点。柴犬豆包大约 40 个 MeshInstance：胶囊身体 + 藏青背心 + 背后 Label3D「PAW」+ 球形头（缩放 1.08×0.94）+ 棱柱耳朵 + 小警帽 + 环面卷尾巴。所有网格经 `Models._mesh_cache` 按尺寸缓存复用。

**程序化走路**（`CharModel.animate`）：

```gdscript
_walk += delta * (4.0 + 11.0 * move01)          # 步频随速度
var s := sin(_walk)
body.position.y = absf(s) * 0.07 * move01 - crouch * 0.17   # 上下颠
body.rotation.z = s * 0.075 * move01                         # 左右摇
body.rotation.x = 0.1 * move01 + crouch * 0.25               # 前倾 / 蹲
foot_l.position.z = _foot_base.z + s * 0.17 * move01         # 迈步
foot_l.position.y = _foot_base.y + maxf(0.0, s) * 0.07 * move01  # 抬脚
```

**等距相机**：`GameCamera` 是一根「臂」：`rotation_degrees = (-45, 45, 0)`，正交相机 `size = 15.5` 挂在臂上 z=60 处。WASD 走的是「相对屏幕」的方向，需要把屏幕方向换算到地面：45° 俯视下地面纵向被压扁成 `sin(45°)` 倍，`screen_to_ground()` 把屏幕 y 除以 `sin(45°)` 反算回来（这个修正后来在手机瞄准上非常关键）。

**世界里的 UI 用 Label3D**：伤害数字、「!」警觉标记、「救命!」气泡、店招「喵喵便利店」（HDR 颜色 ×2.2 配合辉光当霓虹灯）、地上的「欢迎光临」。要盖在场景前面的用 `no_depth_test = true` + `render_priority`。

**关卡**：`MapBuilder` 用 `solid()`（碰撞 + 可视盒子）、`wall()`（可视高度和碰撞高度分开：朝镜头的南墙只露 0.55m 高，碰撞仍是 2.4m，不挡视线）、`MultiMesh` 批量画货架上几百个彩色商品。低矮掩体放在单独的物理层 `LAYER_LOWCOVER = 32`，子弹规则：射手离掩体 1.8m 内可以越过掩体射击，否则被挡。

### 本阶段踩坑

| 坑 | 现象 | 原因 | 修法 |
|---|---|---|---|
| Sfx 方法名 `_get` 撞车 | 访问 Sfx 的属性出现奇怪错误/行为 | `_get(property)` 是 `Object` 的虚函数（自定义属性读取），在脚本里定义同名方法等于重写了属性访问 | 改名为 `_stream(sound)`。**规则：不要用 `_get/_set/_init/_ready/_process/_notification` 等引擎保留名做普通方法名** |
| 敌人沿导航路径走到路点附近原地打转 | 寻路角色卡住 | 导航网格的高度有体素误差（`cell_height = 0.25`），用 3D 距离判断「到达路点」永远达不到 0.35m | 只按**水平距离**推进路点（`enemy.gd` 的 `_nav_dir`），`zombie.gd`、自动测试的 `_follow` 同理 |
| 员工休息室门洞导航不通 | 匪徒/机器人进不去 | 门洞两侧墙在 x=8.0 和 9.6，墙厚 0.3 → 净宽只有 1.3m，导航 `agent_radius = 0.5` 两边各腐蚀 0.5m 后几乎没路 | 墙端改到 7.85 / 9.75，净宽 1.6m（`map_builder.gd` 注释「门洞净宽 1.6m」） |
| 锁着的门要不要进导航 | 破门后要重新烘焙导航（卡一下） | 门的 StaticBody 参与了烘焙 | 先烘焙导航**再创建门**：导航里门洞是通的，锁门只靠物理碰撞挡；员工区匪徒在破门前 `zone_active()` 为假不会行动 |

## 阶段 3：手感 / 「Juice」（v0.1 起持续打磨）

设计稿第六节的清单逐条落地，核心思想：**每一个玩家动作都要在 画面、镜头、声音、时间 四个通道上同时有反馈**。完整数值见 [`references/juice-and-animation.md`](skill/references/juice-and-animation.md)。

| 动作 | 画面 | 镜头 | 声音 | 时间 |
|---|---|---|---|---|
| 开枪 | 枪口星形火光（0.06s 缩小消失）+ 隔一枪一个点光源 + 弹壳抛出弹跳 + 枪身后坐 0.13 | 反向踢 0.14 + 震 0.05 | `shot`（音高 ±8% 随机） | — |
| 命中 | 白闪 + 挤压 0.25 + 击退 + 伤害数字（×10 显示，更爽）+ 火花 | — | `hit` | — |
| 击倒 | 「击倒!」黄字 + 倒地 BOUNCE 动画 + 头顶 3 颗转星星 + 烟尘 | 震 0.3 | `bonk` | 顿帧 0.06s |
| 翻滚 | 整个 pose 绕 X 转一圈 + 起跳 0.25 + 残影拖尾 + 落地烟尘 | — | `roll` | i-frame：子弹穿过显示「闪避!」 |
| 冲撞（Q） | 橙色冲击环 + 橙色闪 + 残影 | 震 0.2，撞到人再震 0.35 | `dash` | 撞人顿帧 |
| 破门 | 门板变刚体被踹飞 + 木屑火花 + 冲击环 + 敌人描边变红 + 「子 弹 时 间」横幅 | 震 0.8 + 缩放 0.86 | `breach` + `slowmo`，音乐低通变闷 | 世界 ×0.25、玩家相对 ×2.4，持续 1.9s |
| 完美换弹 | 「完美换弹!」橙字 + 橙环 + 4 秒火力强化（子弹变橙、伤害 ×1.5） | — | 琶音 `perfect` | — |
| 受伤 | 红闪 + 屏幕边缘红 + 受击方向红弧 + 狗牌抖动 | 震 0.4 | `hit_player` | 0.4s 受击无敌 |

**敌人开枪前的红色激光预警**：浣熊锁定后进入 `_tele` 状态 0.5s（劫持者 0.65s，再乘难度系数），枪口拉一条红色发光细线指向玩家，线宽以 `sin(ms*0.05)` 抖动，同时模型闪红 + `telegraph` 高音，然后 3 连发。玩家看到红线就翻滚 —— 「躲子弹」成为核心乐趣，比单纯血量对拼有趣得多。

**非致命设计**：匪徒血量打空 → 晕倒 14 秒（头顶「可上铐 Ns」青色倒计时，最后 4 秒变「快醒了!」红黄闪烁）→ 走过去按 E 上铐（+150 分，永久制服）；不铐会以 50% 血量醒来。这让「打完还要跑过去铐」形成节奏，也呼应「我们是特警，不是打手」。

**掩体自动蹲**：玩家速度 < 2.5 且离低掩体 0.7m 内就 `in_cover`，模型蹲下（body 下沉 0.17、前倾 0.25），狗牌上出现青色盾牌「掩体」。

## 阶段 4：UI 设计语言（v0.1）

主题定为 **「贴纸 / 警局档案」**：所有面板都是「实物」——钉在软木板上的照片、便利贴、警员证、对讲机、报纸。完整规范见 [`references/ui-design.md`](skill/references/ui-design.md)。

| 界面 | 隐喻 | 关键动效 |
|---|---|---|
| 主菜单 `main_menu.gd` | 软木任务板：标题纸（-2°）+ 黄色便利贴（+3°，胶带）+ 5 张案件拍立得（红色图钉、红线下垂 34px 连起来）+ 小队名单 | 照片依次「啪」地钉上（间隔 0.09s，BACK 回弹）；悬停翘起放大 1.08、阴影加深、橙色光边；点未解锁的照片左右抖 + 「机密」章 |
| 简报 `briefing.gd` | 黑屋里的投影仪：光锥 + 扫描线幕布 + 平面图（虚线路线流动）+ 可翻面警员证 + 局长打字机台词 + 难度选择 | 开场黑幕按 `[0.3, 0.9, 0.1, 0.7, 0.0]` 闪烁（投影仪接触不良）；证件翻面 = `scale.x` 1→0→1 |
| 转场 `game.gd` | 三条黄黑警戒线胶带交错扫过 | 0.32s 进 / 0.34s 出，错开 0.05~0.06s |
| HUD `hud.gd` + `hud_widgets.gd` | 狗牌血条（珠链、10 段平行四边形血格）、罐头弹药（30 个小罐头）、目标「药丸」横幅、对讲机对话框 | 狗牌受击抖动、残血闪白、弹药数字每枪「跳」一下 |
| 暂停 `pause_menu.gd` | 背景模糊 + 右侧滑出对讲机 | BACK 回弹滑入 0.35s |
| 结算 `results.gd` | 《毛绒日报》头版：报头、头条按评级变、照片、广告位、战报 | 报纸转 3 圈飞入、战报逐行打字、分数滚动、评级印章从 3 倍「啪」地盖下 + 整版震动 |

**字体**：站酷快乐体（标题/按钮，圆润可爱）、思源黑体 SC Medium/Black（正文，**子集化**为 GB2312 一级字 3755 字 + ASCII + 常用标点 + 代码里出现的所有字符，`fontTools` 实例化可变字重 500/900）、Bungee（数字和英文招牌）。全部 OFL 授权，许可证文件随工程放在 `assets/fonts/`。

**所有 HUD 小部件都 `_draw()` 自绘**：狗牌、弹药、准星、技能圈、目标横幅、屏幕边缘箭头、触屏按钮。好处是动画就是改几个 float 然后 `queue_redraw()`，不需要 AnimationPlayer；风格统一（粗 INK 描边 + 偏移阴影 `Color(0,0,0,0.35)`）。

**头像也是代码画的**：`Portrait.draw_face(ci, center, r, species)` 支持柴犬、局长、仓鼠、浣熊、老鼠、黑猫、金毛、三花 8 种，按耳朵类型（尖/圆/大/垂）+ 配色表组合。

## 阶段 5：音频全部代码合成（v0.1）

`sfx.gd` 里写了一个迷你合成器：`_add_tone`（正弦/方波/三角/锯齿，频率指数滑动 + 指数衰减包络 + attack）、`_add_noise`（一阶低通噪声，可高通）、`_add_bell`（三个泛音）。用这三个积木拼出 47 个音效和 3 首循环音乐（菜单 lo-fi 84 BPM、战斗 118 BPM、僵尸潮 150 BPM）。详见 [`references/audio.md`](skill/references/audio.md)。

总线：`Master ← SFX / Music`，Music 总线上挂一个 700Hz 低通（默认关闭），进入子弹时间时打开 = 「音乐被闷住」的电影感（`Game.bullet_time()` → `Sfx.muffle(true)`，结束或 `reset_time()` 时关闭）。

**踩坑：运行时合成导致卡顿**（阶段 11 修）—— 第一次播放某个声音时要在 GDScript 循环里算几千到几十万个采样（音乐一首 4 小节、22050Hz），主线程直接卡一下。修法：`tools/bake_audio.gd` 离线把所有声音存成 `assets/sfx/*.wav`，运行时 `_preload_baked()` 启动即全部 `load()`，音乐设置 `LOOP_FORWARD`；只有缺文件时才回退到现场合成。

## 阶段 7：第一轮反馈 —— 「WASD 不会转身」+ 「主要在手机/平板上玩」（v0.2，`adf8545`）

### 反馈 1：WASD 移动时角色不转身
原设计是双摇杆：角色永远面向鼠标。用户在不动鼠标只按 WASD 时，角色倒着走，很怪。

**改法**（`player.gd`）：朝向优先级 = 翻滚方向 > 冲撞方向 > 开火/精瞄（及之后 0.35s 余韵）朝准星 > 移动方向。转身速度开火时 70（瞬间转过去，保证枪口和子弹方向一致），平时 20。

```gdscript
if _held("shoot") or aiming:
	_face_aim_t = 0.35
else:
	_face_aim_t -= d
var face := facing
if roll_t > 0.0: face = roll_dir
elif dash_t > 0.0: face = dash_dir
elif _face_aim_t > 0.0: face = aim_dir
elif wish.length() > 0.15: face = wish
face_toward(face, d, 70.0 if _held("shoot") else 20.0)
```

### 反馈 2：平台以手机/平板为主
这是整个项目的转折点：**所有交互都要重新为拇指设计**。

- 输入抽象：`Player` 原本就有 `bot_enabled + bot{}` 字典（给测试机器人用）。触屏控件 `TouchControls` 直接往 `player.bot` 写 `move / shoot / aim_point / just_roll …`，**和键鼠共用同一套角色逻辑**，测试机器人也走同一条路。
- 触屏自动识别：`OS.has_feature("mobile")`、网页上 `web_android / web_ios`、或 `web` + `DisplayServer.is_touchscreen_available()`；电脑上 `-- --touch` 预览。
- 手机 HUD 布局（`Hud._touch_layout`）：底部两角留给拇指，狗牌缩到 0.8 移到左上，对讲机放它下面；弹药面板、技能面板、准星隐藏（这些信息挪到触屏按钮上）。
- 屏幕适配：设计分辨率 1920×1080，`stretch/mode="canvas_items"` + `aspect="expand"`，所以 20:9 手机会变宽、4:3 平板会变高；所有界面用「居中 1920×1080 的 board + 锚点贴边的 HUD」两种方式布局。
- 安卓返回键 = 暂停/关闭暂停/回菜单；切到后台自动暂停（`NOTIFICATION_APPLICATION_FOCUS_OUT / PAUSED`）。
- 震动：开火按下 8ms、按钮 12ms、受伤 40ms、强震屏 15~60ms，可在暂停菜单关掉。

**踩坑：自动测试注入触屏坐标不对**。`InputEventScreenTouch.position` 要的是**窗口像素坐标**，而游戏逻辑在 1920 宽的 canvas 坐标里；窗口比例不同时还会多出 expand 区域。修法：注入前乘上视口最终变换，且测试窗口用和基准同比例的 `--resolution 2400x1080`。

```gdscript
e.position = get_viewport().get_final_transform() * pos
```

## 阶段 8：第二轮反馈 —— 「射击不听话」→ 调研 → 瞄准重做（v0.3，`f29cead`）

### 反馈
手机上开火时目标乱跳、拖动瞄准方向和手指方向对不上、打人质附近的敌人容易误伤。

### 调研：手机射击游戏怎么设计瞄准
看了几类代表作的做法：
- **弓箭传说（Archero）**：站定自动射最近的敌人，移动就不射 —— 零操作但没有主动权。
- **荒野乱斗（Brawl Stars）**：右摇杆「点按 = 自动瞄准最近目标」，「拖动 = 手动瞄准并显示瞄准线，松手发射」。
- **元气骑士 / 一类俯视射击**：按住开火自动锁定，锁定目标会**持续保持**直到失效（sticky），并在目标脚下画锁定框。
- 通用经验：自动瞄准要「黏」（不要每帧选最近的导致左右横跳）、要可见（玩家知道在打谁）、要能覆盖（点敌人切换、拖动手动）、手动瞄准给轻微吸附而不是硬吸。

### 方案（`touch_controls.gd`）
1. **浮动开火摇杆**：右半屏任意位置按下就在那里出现开火摇杆。不拖 = 自动锁定连射；拖超过 42px = 手动瞄准。
2. **粘性锁定**：已锁定的目标只要还活着、在 13.5+2m 内、射线打得到、不会误伤人质，就一直打它；失效才重新挑。挑选打分 `距离 × (1 + 0.35 × (1 - 面朝点积))`，优先面前的，避免突然转身打背后。
3. **可见**：锁定目标脚下画红色旋转锁定框（椭圆 y 压扁 0.55 贴合等距地面）+「锁定」字；不开火时用半透明白框预告「下一个会打谁」（每 0.15s 计算一次）。
4. **点敌人切换锁定**。
5. **手动瞄准修正 45° 透视**：`cam.screen_to_ground(drag_dir)`，手指往屏幕右上拖，子弹就飞向屏幕右上 —— 「指哪打哪」。
6. **轻微吸附**：手动方向 7° 以内有敌人时，`slerp` 60% 拉过去。
7. **子弹磁性**：玩家子弹对锁定目标在 14° 内以最多 90°/s 转向（不会拐弯，只修小偏差）。
8. **人质安全**：如果「玩家→目标」射线（延长到目标后方 8m，因为打偏的子弹会继续飞）离人质 < 1.0m，或目标离人质 < 1.4m，就不自动锁定，提示「人质在旁边 —— 拖动开火键手动瞄准！」。
9. **可选「松手射击」**（荒野乱斗式，暂停菜单切换）：拖动只显示黄色虚线瞄准线，松手打出一轮（步枪 0.36s、激光 0.7s、加特林 0.5s、散弹/火箭一发）。
10. 手机上**不靠散布制造难度**：散布从电脑的 `1.4° + bloom + 移动×3°` 降到 `0.5° + bloom×0.25 + 移动×0.6°`；镜头不再跟随准星前瞻，只沿朝向前瞻 2.5m，开火时不晃。

细节与数值见 [`references/mobile-controls.md`](skill/references/mobile-controls.md)。

## 阶段 9：高潮段落 —— 神装、僵尸鼠潮、像素变身、空投（v0.3，`f29cead`）

### 为什么要加
原序章在救出人质后就结束，节奏是「紧张 → 破门高潮 → 结束」，缺少一个让玩家「爽到」的收尾。用户希望结尾有大场面。设计成：救出人质 → 实验罐头泄漏 → 可爱款僵尸鼠潮 → 空投神器 → **变身特写 + FIRE!** → 坚守 60 秒 → 空投炸弹清场。

### 神装武器（敌人掉落）
| 武器 | 弹药 | 间隔 | 特性 |
|---|---|---|---|
| 喵喵散弹（收银台浣熊掉） | 18 | 0.5s | 扇形 34° 8 发，射程 11m，击退 ×2.6，自身后坐 |
| 罐头激光（仓库浣熊掉） | 110 | 0.06s | 射线贯穿一排（最多 14 次穿透），碰墙停 |
| 肉垫火箭（劫持者掉） | 10 | 0.7s | 速度 24，爆炸半径 3.4，伤害随距离 1→0.5 衰减 |

全部神装子弹 `safe = true`：射线 mask 去掉人质层，「友军识别不伤人质」，避免高潮时误伤失败。
**小修 `4a99f73`**：加特林原本 420 发，测试发现撑不到 60 秒，改成 1400。

### 可爱款僵尸鼠
薄荷绿圆滚滚身体、一大一小的呆萌眼睛、缝线小嘴 + 吐舌头、头顶交叉创可贴；从地里「钻出来」（模型从 -1.3 倍身高 BACK 回弹升起）；被打败变一团绿烟 + 小幽灵飘走（不血腥）；鼠王 2.3 倍大、戴金冠、45 血（×难度）。

### 30 FPS 像素风变身动画（`ui/cutscene.gd`）
想要「变身特写」的漫画感，又不想做 3D 过场：
- 一个 `SubViewport` 320×180（`disable_3d`、`canvas_item_default_texture_filter = NEAREST`），里面一个 `PixelCanvas` 用 `_draw()` 逐帧画；外面一个全屏 `TextureRect`（`TEXTURE_FILTER_NEAREST`）放大 → 硬像素边缘。
- **自己累计真实时间，按 30fps 步进帧号**（`_acc >= 1/30` 就 `_f += 1`），共 108 帧 = 3.6 秒；播放期间 `get_tree().paused = true`，Cutscene 自己 `PROCESS_MODE_ALWAYS`。
- 分镜：0–30 黑边推入 + 放射速度线 + 豆包头像滑入 + 眼睛闪光；30–60 零件从四面八方飞来组装（每到一件 `clank` + 小抖 + 白色四角星）；60–80 背景变橙、光圈、「神器装备！」；80–108 背景变红、张嘴、「FIRE!」从 3.2 倍砸下 + 抖屏 + 合成喊叫 `shout_fire`。
- 黑边、闪白放在**全分辨率层**上平滑过渡，像素层只画内容。

**踩坑**：
- `0320d3a` 宽屏手机（20:9）上画面被裁掉两边：`STRETCH_KEEP_ASPECT_COVERED` → 改 `STRETCH_KEEP_ASPECT_CENTERED`（两边留黑）。
- `4017f9d` 字幕被黑边挡住：黑边高度 11% → 7%，字幕 y 30→42、166→158。

### 结尾空投
坚守 60 秒后：局长「趴下！！」→ 1 秒后全屏闪白 1.0 + `explosion`（音高 0.7）+ `breach` + 震屏 1.0 + 子弹时间 2.4s + 16m 冲击环 → 场上僵尸在 0.05~0.9s 内随机依次「噗」掉（60% 静音避免爆音）→ 「任务完成」横幅 + 胜利琶音 → 劫持者冷笑「老K 会来接我的」（续作伏笔）→ 6 秒后进结算。

## 阶段 12：性能大修（`566f20a`）

### 方法
测试机器人加帧耗时统计：每帧算真实间隔，> 50ms 记一次 `[hitch]`，打印当时的步骤 / 关卡阶段 / 僵尸数，结束时输出 `[perf] frames=… hitches(>50ms)=… worst=…ms`。先测基线，再逐项改，每改一项重跑对比。

### 结果
完整通关一局：**卡顿帧（>50ms）11 次 → 2 次，最差帧 395ms → 79ms**。

### 改了什么

| 问题 | 定位 | 修法 |
|---|---|---|
| 第一次播放音效/音乐卡 | 运行时合成 | 离线烘焙 WAV + 启动预载 |
| 第一次出现某种特效/模型卡（着色器编译） | hitch 出现在「第一次开枪」「第一只僵尸」「第一次捡神装」 | `Level._prewarm()`：在转场胶带遮挡期间，把所有特效、僵尸、鼠王、幽灵、5 种武器模型、星星、各色子弹在玩家附近各生成一次，0.35s 后删除 |
| 特效每次都 new 网格/材质/曲线 | 频繁分配 | `Fx._res` 缓存：quad、火花网格、淡出曲线、烟尘网格/材质按颜色缓存；`Toon.prop/glow` 按颜色缓存 |
| 残影复制整个角色模型（40 个节点） | 翻滚/冲撞时每 0.045s 一次 | 改成两块半透明剪影（胶囊 + 球） |
| 弹壳无限堆积 | 加特林 1400 发 | `MAX_SHELLS = 36`，寿命 3 秒，最后 0.5s 缩小消失；加特林每 3 发才抛一个 |
| 枪口点光源太多 | 每发一个 OmniLight | 步枪隔一枪、加特林每 4 枪才带灯 |
| 顿帧叠加导致「卡住」感 | 加特林 + 一群僵尸每帧都顿 | 顿帧上限 0.06s + 350ms 冷却；玩家受伤、爆炸不再顿帧 |
| 破门后重烘焙导航 | 运行时 bake | 门创建前烘焙一次 |
| 全屏后处理一直开着 | screen_fx 每帧都读屏幕纹理 | 只有子弹时间/受伤/低血时才 `visible` |
| 手机物理太重 | 120Hz 物理 | `physics_ticks_per_second.mobile/web = 60`，桌面 120 |
| 触屏候选目标每帧大量射线 | `_pick_target` 每帧 | 不开火时每 0.15s 算一次 |

## 阶段 13：新手提示卡（`566f20a`，v0.5 修 BUG，v0.6 重做位置）

- 暂停菜单「操作说明 ？」页：两列网格列出全部 12 张卡。

**v0.5 BUG：提示卡永远不消失**。原代码在时间到后同时执行「淡入」和「淡出」，淡入速度 5/s 比淡出 4/s 快，alpha 永远回不到 0。修法：只有 `_left > 0` 时淡入，时间到只淡出。测试机器人加了 `_tip_watch()`：同一张卡在屏上超过 15 秒就打印 `[tip] STUCK`。

```gdscript
if _left > 0.0:
	_a = minf(1.0, _a + rd * 5.0)
else:
	# 时间到：只淡出（之前淡入和淡出同时进行，淡入更快，卡片永远不消失）
	_a = maxf(0.0, _a - rd * 4.0)
	if _a <= 0.0:
		_cur = ""
```

**v0.6 改版**：卡片原来在屏幕中上方挡战场 → 移到**左侧、局长对讲机下面**（桌面 y=200，手机 y=332），从左边滑入 60px；正文里用 `{关键字}` 标记，`Tips.rich()` 转成红色加粗 BBCode（`#FF5C5C`），`Tips.plain()` 去掉标记用于算阅读时长；左上角黄色「新手提示」标签。

## 阶段 14：最速通关排行榜（v0.4，`e6c5224` `1871c1d`）

### 需求
做一个速通排行榜，不想让玩家注册账号。

### 设计
- **游客身份**：第一次联网自动用随机昵称（「爱吃罐头的柴犬42」这类）注册，服务器返回 `player_id` + **恢复码** `PAW-XXXX-XXXX-XXXX`（去掉易混字符 0/O/1/I）。恢复码既是登录凭证也是换设备找回方式，服务器只存 SHA-256。存在 `user://profile.cfg`。
- **计时**：真实时间（`Time.get_ticks_usec` 差值，单帧最多计 100ms），暂停菜单和变身动画期间整棵树暂停，`Level._process` 不跑，自然不计时。
- **本机记录**：每个难度保留前 20 条。
- **结算页**：右上角「最速通关」便签（用时、难度色块、个人最佳 / 本机排名 / 全球排名 / 「新纪录！」徽章），第一次上榜弹「给自己起个特警代号」对话框（带「随机」按钮）。
- **排行榜页**：全球榜 / 本机记录 tab + 四个难度按钮；右侧「我的特警证」：昵称、改昵称、恢复码、复制、用恢复码找回。前三名金/银/铜色排名，「我」那一行橙色高亮（服务器只返回 player_id 前 8 位用于识别）。

### 服务器（`server/leaderboard/`，Cloudflare Worker + D1）
防作弊思路：**服务器不信任客户端上报的时间，只信自己测的时间**。

| 校验 | 实现 |
|---|---|
| 每局一个令牌 | `/api/run/start` 记录 `started_at` 和难度，返回 `run_token` |
| 令牌一次性 | `/api/run/finish` 先把 `used=1` 再校验，无论成败 |
| 不能比服务器经过的时间短 | `time_ms > serverMs + 3000` → `time_mismatch` |
| 物理下限 | `time_ms < 75000`（僵尸潮固定 60 秒）→ `too_fast` |
| 必须真的完成 | `rescued === true`、击倒数 ≥ 难度下限（easy 7 / normal 9 / hard 13 / insane 19）、僵尸 ≥ 8 |
| 难度不能改 | 以开局时绑定在令牌上的难度为准 |
| 频率限制 | 每人每小时最多 60 局；单局最长 1 小时 |
| 昵称清洗 | 去控制字符和 `<>`，最多 12 字 |

`test/api_test.mjs` 用 node 打本地 `wrangler dev`：错误密钥 401、太快、令牌复用 409、上报时间大于服务器时间、未完成、非法难度、恢复码大小写、改名；`--wait` 真实等待 76 秒提交一条合法成绩，验证排名和「提交时改难度无效」。

**小坑 `1871c1d`**：tab 切换后高亮不变 —— `StickerButton` 的配色在 `_init(kind)` 里一次性设好，切换时直接按新 kind 重建按钮替换。

### iPhone 网页版：没声音、手势乱、不能全屏
用户在 B 站 App 里打开（bilibili TOY 嵌入页）发现摇杆和开火键不好使、横屏界面很怪；换 Safari 后操作正常，但没有声音。

- **分析先行**（用户要求先不改代码）：截图里游戏被嵌在一个约 1118×255 的扁框里（宽高比约 4:1），`canvas_items + expand` 按短边缩放，按钮被缩到极小；App 内置浏览器还会把左边缘滑动当成返回手势。iPhone 的 Safari 不支持元素全屏 API，网页**没法自动全屏**，可行路线是「添加到主屏幕」（PWA）、Safari 隐藏工具栏、或做原生 iOS 版。
- **没声音**：iPhone 静音开关会让 Web Audio 完全静音；且 iOS 只允许在 `touchend`/`click` 里恢复 AudioContext。修法放在网页导出的 `html/head_include`（源码 `game/web/head_include.html`）：
  1. 包装 `window.AudioContext` 构造函数，记下 Godot 创建的实例；
  2. 第一次触摸/点击时 `navigator.audioSession.type = "playback"`，并循环播放一段 0.2 秒的静音 WAV（`<audio>` 元素）——这会把 iOS 的音频会话切到「播放」类，之后不受静音开关影响；
  3. 在 `touchend / click / keydown / pointerup` 里对所有 AudioContext 调 `resume()`；页面切到后台时暂停静音音频，回来后下一次触摸再恢复。
- **防误触**：CSS `touch-action:none`、`-webkit-touch-callout:none`、`user-select:none`、`overscroll-behavior:none`，并对 `gesturestart`、`dblclick`、多指 `touchmove` 调 `preventDefault()`。
- 这一部分只能在 Chromium 里验证「无报错、AudioContext 被捕获」，iPhone 真机上的声音和手感需要用户确认。

### 1. iOS 摇杆
- 先在 Chromium 里用 CDP `Input.dispatchTouchEvent` 驱动网页版：从菜单点到关卡，按住左下拖动 → **摇杆正常**。说明问题只在 iOS 上。
- v0.6 的网页外壳在 `document` 上加了非被动的 `touchmove` / `dblclick` 拦截，这是 v0.6 唯一和触摸有关的改动 → 全部删掉，只保留音频解锁和 canvas 上的 `touch-action:none`（教训写进了 `head_include.html` 的注释）。
- 触屏层改成「**新手指接管**」：左半屏任何新按下的手指都接管摇杆，右半屏的接管开火键。iOS 偶尔会丢 `touchend`（系统手势、来电横幅、切后台），旧逻辑里 `_move_idx` 会一直占着，摇杆就「死」了。
- 新增触摸调试叠层：网页地址加 `?debug=touch`（`JavaScriptBridge.eval("window.location.search")` 读取）或命令行 `--touchdebug`，画出每根手指的编号和位置，顶部列出最近 8 条按下/抬起事件以及当前摇杆/开火键绑定的手指。真机上出问题时让用户录屏即可定位。

## 复盘：这个项目「做对了」的几件事

1. **先设计后编码**：设计稿里的「手感清单」和「界面隐喻表」变成了后续每个阶段的验收标准。
2. **所有数值都是命名常量或集中表**（`Player.SPEED`、`Game.DIFFS`、`Weapons.DATA`、`Pal.*`），调参不用找代码。
3. **输入抽象层**（`player.bot`）：键鼠、触屏、测试机器人三种输入走同一套角色逻辑，所以触屏和测试几乎是零成本接入。
4. **测试机器人真的在玩游戏**：从菜单点到结算，带截图、卡顿统计、提示卡卡死检测、触屏断言；每一轮修改都跑一遍再交付。
5. **每次反馈都先复述再改**：「射击不听话」被拆成「目标乱跳 / 方向对不上 / 误伤人质」三个具体问题，各有对应方案。
6. **用户看得到的东西一律做动画**：没有任何一个数字、面板、按钮是「瞬间出现」的。
7. **交付物带说明**：每个 zip 里都有一份 `说明.txt`（怎么装、怎么玩、限制）。
